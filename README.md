## Архитектура

`collector` получает публичные структурированные ответы, которыми пользуется сам сайт. Проверяет категории и точные множества ID, затем обновляет новые/изменившиеся карточки. SQLite хранит неизменяемые наблюдения, события и долговечную очередь публикаций. `api` предоставляет HTTP и MCP над той же базой. Отдельный `bot` получает решения модераторов и доставляет сообщения. LLM извлекает до трёх фактов с проверяемыми дословными цитатами.

## Запуск

Нужен Docker Desktop с Linux containers или Docker Engine с Compose. База хранится в named volume `kiravto_stock`; локальная база разработки с ней не объединяется.

1. Человек настраивает локальные секреты по шаблону `.env.example`. Для Windows есть `setup-secrets.ps1` и `connect-telegram.ps1` со скрытым вводом. Токены в Git не добавляются. Подключение модераторов выполняется человеком.
2. Из корня репозитория: `docker compose up --build`. Запускаются API на `127.0.0.1:8000` и сборщик с интервалом по умолчанию 3600 секунд.
3. После настройки группы и разрешённых moderator ID: `docker compose --profile telegram up --build -d`.

Профиль по умолчанию — test, канал `@autostock_demo_test`. Автоматическое создание предложений и LLM выключены. Человек может разрешить `POST_JOBS_ENABLED=true` для предложений по новым объявлениям/снижениям; публикация всё равно требует кнопки модератора. Боевой режим включается только человеком, отдельно от агента. Запускать два сборщика или два bot-worker над одной базой одновременно не нужно.

### Особенность сети тестового Windows-ПК

Для Авто.ру пользователь настроил прямой маршрут Docker через раздельное туннелирование. Telegram в этой конфигурации проверен через локальный TLS-помощник: `python tools/telegram_tunnel.py`, затем `docker compose -f compose.yaml -f compose.local-vpn.yaml --profile telegram up -d --no-deps bot`. Старый bot-worker перед сменой подключения останавливается. Помощник разрешает только CONNECT к api.telegram.org:443, не расшифровывает TLS и должен оставаться запущенным. На другой сети этот override может не требоваться. Капча, HTTP-отказы и региональные ограничения защиты не обходятся.

## Проверки без сети

Нужен Python 3.12. Создать venv, установить `requirements-dev.txt`. На Windows использовать `.venv/Scripts/python.exe`, на Linux — `.venv/bin/python`.

Первым запуском **из этого venv** выполнить `python tools/configure_agent.py`: он заменит переносимые шаблоны конфигурации на пути текущего клона. Это необходимо и для Windows-теста реального запуска hooks. Затем `python -m unittest discover -s tests -v`.

Для Linux-проверки в контейнере: сначала `docker compose build api`, затем `python tools/test_docker.py`. Контейнер тестов запускается с network=none и временной базой, без рабочего volume и секретов. Windows-специфичные тесты там пропускаются. Исторический результат: 124 теста на Windows и Docker; после защиты генераторов — 129 в Docker и 7 целевых Windows-тестов; точные проверки пакета указаны в evidence/ПРОВЕРКА_ПАКЕТА.md.

## API и MCP

`GET /health` доступен без токена; `/offers`, `/offers/{id}`, `/offers/{id}/history`, `/stock`, `/drops`, `/runs`, `/report`, `/openapi.json` требуют `Authorization: Bearer <API_TOKEN>`. Без токена — 401, некорректная пагинация — 422.

Свой MCP запускается из корня командой `docker compose exec -T api python -m kiravto mcp`. Настройки — `.mcp.json` и `.codex/config.toml`; для путей нового клона выполнить configure_agent.py. Семь инструментов: поиск, карточка, история, снижения, склад, статусы прогонов, предложение поста. Прямой публикации нет. Перед выводами о складе проверять run_status и время наблюдений.

Hooks подключаются после личного просмотра и доверия пользователя. В исходной рабочей сессии подтверждены реальный SessionStart и отказ PreToolUse на безопасном отрицательном примере; тесты также проверяют эти сценарии. Агент не подтверждает доверие вместо человека.

## LLM-факты по одной карточке

Из папки проекта сначала выполните предпросмотр без обращения к модели:

```powershell
docker compose run --rm --no-deps api python -m kiravto facts 1160076098-ba703ee3 --dry-run
```

Чтобы обработать описание именно этой сохранённой машины:

```powershell
docker compose run --rm --no-deps api python -m kiravto facts 1160076098-ba703ee3
```

Вместо ID можно передать полную HTTPS-ссылку на карточку `auto.ru` в кавычках. `--json` включает структурированный вывод. Команда не собирает сайт и не публикует сообщения: результат сохраняется для API/MCP и будущих предложений. Чужой домен, неизвестный ID и непроверенная карточка не отправляются модели. Нужен локально сохранённый `LLM_API_KEY`; ручная команда работает и при `LLM_ENABLED=false`.

Автоматическая обработка теперь требует отдельного явного разрешения **`LLM_AUTO_ENABLED=true` вместе с `LLM_ENABLED=true`**. По умолчанию `LLM_AUTO_ENABLED=false`: один сохранённый ключ или включённый прежний флаг не запускает обработку всего склада. Настроенный дневной бюджет общий для ручных и автоматических вызовов; расчёт дня ведётся по UTC.

Повтор команды для того же точного описания использует кэш. Неудачный/прерванный запрос не повторяется автоматически и не сбрасывает неизвестные расходы. Поддержаны только бесплатные маршруты модели; это не обещание доступности или нулевой тарификации провайдером. В выводе — до трёх проверенных цитат и учёт сохранённого запроса, без ключа. Если описание состоит из рекламы салона, ноль фактов — нормальный результат. Свежесть цены эта команда не проверяет.

Новые ошибки различают HTTP-код, сетевую недоступность и неверный формат ответа. Сохраняются только категория и числовой статус: тексты ответов, ключи и заголовки не записываются. Причина прежней общей ошибки может оставаться неизвестной. Запреты доступа провайдера не обходятся; повтор команды не сбрасывает кэш или резерв. Подсказка Docker про Gordon после ненулевого кода завершения не означает, что причиной является Compose.

## Источник, история и ограничения

При изменении выдачи во время перечисления счётчик родителя ценового диапазона перечитывается. Принять новый счётчик можно только при точном совпадении с числом уникальных ID дочерних диапазонов и подтверждении строк контрольной страницы в том же поддереве. Старое и новое значения остаются в доказательствах. Если валидные ответы всё ещё противоречат друг другу, допускается одна новая попытка сбора с чистым набором ID и прежним кэшем проверенных карточек. Первая неполная попытка остаётся в истории; `collection_attempts`, `collection_total_requests` и `collection_total_seconds` показывают расходы всего цикла. HTTP-отказы, капча, неверный JSON, изменение схемы/фильтров, неверная цена и исчерпание лимитов дополнительную попытку не получают. Независимые ALL/USED/final-root, отдельное подтверждение отсутствующих ID и порог покрытия 90% сохранены. Это повышает устойчивость, но не гарантирует успех на непрерывно меняющемся источнике.

Источник — публичный RIS API и собственная анонимная сессия. Перечисление ALL разбивается на проверенные диапазоны скидочной цены; категории и ID сверяются повторно. Прямой NEW-запрос может иметь скрытые ограничения, поэтому новые вычисляются как ALL минус независимо собранный USED. Подробности кэшируются по маркерам источника; частые source_updated_at могут требовать большого числа карточек заново.

Неполный прогон и сбор менее 90% последнего полного склада запрещают снятия. Для отсутствующего ID отдельно требуется matching-ответ INACTIVE/REMOVED. Возврат объявления, новый ID той же машины и вероятная продажа различаются. Снятие само по себе не доказывает продажу. Идентичность уверенно связывается по полному VIN; частичные VIN и прочие эвристики не выдаются за доказательство.

Обе цены и условия скидок сохраняются отдельно. Оригинальные URL фото сохраняются в порядке источника; первый файл декодируется и хешируется с TTL доказательства 24 часа. Все остальные файлы постоянно не скачиваются. Неподтверждённые поля явно перечислены, а не выдуманы.

Успешная живая LLM-проба выполнена на явно синтетическом тексте: 3 точные цитаты, один запрос, повтор из кэша, стоимость 0 по данным провайдера. Реальные описания автомобилей в этой пробе не отправлялись. Бюджет и неизвестные расходы учитываются; автоматические вызовы выключены по умолчанию. Новая ручная команда проверена без сети и предпросмотром; новый живой ответ провайдера на реальное описание не заявляется.

История началась 22 октября; полной недели ещё нет. 29 событий снижения не менее чем на 5% относятся к 23 объявлениям, а не к 29 разным машинам. Проверка live-источника отражает согласованность в интервале, а не атомарный снимок рынка.

Предложения обоих типов требуют active/source_complete и наблюдения last_seen не старше двух часов. Для снижения текущая обычная/скидочная цена дополнительно должна совпадать с событием after; старое снижение после отскока цены не предлагается. Свежесть проверяется при создании предложения.
